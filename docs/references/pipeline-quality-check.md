# 파이프라인 품질 검수 규칙

크롤 파이프라인이 **얼마나 모으고**, 모은 것이 **얼마나 쓸모 있는지**를 같은 방식으로 반복 측정하기 위한 규칙. 결론은 항상 셋 중 하나로 떨어진다 — **필터를 강화한다 / refine 을 강화한다 / 수집을 넓힌다**.

- 실행: `bun run scripts/pipeline-quality-report.ts --remote --days=7 --sample=30 --out=data/pipeline-qa`
- 주기: 주 1회. 파이프라인 코드(필터·매칭·요약)를 고친 직후에는 1회 추가.
- 산출: `data/pipeline-qa/<날짜>-report.md` + 표본 3종

## 1. 왜 자동 지표만으로는 안 되는가

수율·백로그는 SQL 로 센다. 그러나 **"이 근거가 유의미한가"는 읽어야 안다.** 특히 중요한 건 버린 쪽이다.

- 통과분만 보면 **false positive**(쓰레기를 통과시킴)만 보인다 → 필터를 조이는 방향으로만 판단이 쏠린다.
- 좋은 글을 버리고 있는지(**false negative**)는 버린 것을 봐야 안다. 그래서 탈락 행의 1%를 30일간 남긴다 (`raw-retention.ts` 의 `AUDIT_SAMPLE_*`). 이 예외가 없으면 크론이 2시간 안에 지워 표본이 사라진다.

## 2. 측정 항목

### A. 수집량·수율 — `pipeline_daily_stats` (0056)
종결 raw 를 지우기 시작한 뒤로는 DB 사후 집계가 불가능하다. 크론이 회차마다 카운터를 남긴다.

| 지표 | 의미 |
|---|---|
| `crawl:*` | 크롤러별 raw 유입 |
| `fulltext:ok` / `fulltext:failed` | 본문 수집 성공·실패 |
| `filter:pass` / `filter:drop` | 룰 필터 판정 (운영에서는 큐 소비자가 기록) |
| `match:sources` / `match:links` | 매칭 산출 |
| `purge:raw_rows` | 삭제된 원장 행 |

> 회차가 `canceled` 되면 그 회차 카운터는 통째로 빠진다 (2026-09-04 06:00 UTC 실측). 일 단위 추세로 읽을 것.

### B. 백로그·지연
단계별 대기 행수와 **최고령**. 행수보다 최고령이 중요하다 — 처리량이 유입을 따라가는지는 나이가 말한다.

### C. 사후 탈락률 — 필터 누수의 1급 지표
룰 필터와 매칭을 통과해 `web_sources` 까지 들어온 뒤 FILTER_V2 가 버린 비율.
**높다 = 상류 필터가 새고 있다.**

전체 기간으로 보면 룰이 없던 시절 행이 섞이므로 **최근 N일 유입분**을 따로 본다. 실제로 2026-09-04 기준 전체 45.6% vs 최근 7일 15.8% 로 3배 차이가 났다.

### D. 커버리지
근거 보유 lot / 근거 3건 이상 lot(요약 생성 가능선) / 요약 보유 lot. 필터·refine 이 아니라 **수집 확대**가 답인지를 가른다.

### E. 표본 (자동 지표로 못 보는 것)
| 표본 | 대상 | 판정 질문 |
|---|---|---|
| `sample-passed` | 최근 매칭된 `web_sources` | 이 글이 **이 주차장의 주차 경험**을 말하는가? |
| `sample-rejected` | 보존된 탈락 표본 | 버린 게 맞는가? 살릴 만한 주차 정보가 있으면 오폐기 |
| `sample-summary` | 최근 생성된 종합 요약 | 요약이 근거와 일치하고 사실인가? |

| 지표 | 실측 | 임계값 | 근거 |

## 4. 표본 검수 절차

1. 스크립트가 표본 3종을 마크다운으로 뽑는다 (기본 각 30건).
2. **Haiku 로 라벨링한다.** 비용 민감 배치이므로 `model: "haiku"` 를 명시한다. 청크 20~30건.
3. **사람은 전량을 보지 않는다.** 다음만 본다.
   - Haiku 가 `애매` 로 라벨한 건
   - `sample-rejected` 에서 오폐기로 판정된 건 (필터 완화는 되돌리기 어려우므로 전건 확인)
   - 라벨 분포가 직전 회차 대비 10%p 이상 움직인 항목

### 라벨 루브릭 (3종 공통)
| 라벨 | 뜻 |
|---|---|
| `유효` | 그 주차장의 주차 경험·요금·진입·혼잡을 실제로 담고 있다 |
| `무관` | 다른 주차장 이야기이거나 주차 내용이 없다 (동명이지 포함) |
| `재배포` | 공공데이터·타 사이트를 옮긴 정보 모음 글 (애그리게이터) |
| `애매` | 위 셋으로 못 가르겠다 → 사람이 본다 |

`재배포` 를 `무관` 과 분리하는 이유는 처방이 다르기 때문이다. 재배포는 **도메인 차단**(`aggregator-domains.ts`)으로 끝나지만, 무관은 **매칭 점수**(`scoring.ts`)를 고쳐야 한다.

## 5. 판정 트리

순서대로 본다. 먼저 걸리는 것이 이번 회차의 처방이다.

1. **`sample-passed` 의 `재배포` 비율 > 10%** → **필터 강화**. 도메인 목록 보강이 1순위 (raw 단계에서 끊는 게 가장 싸다).
2. **`sample-passed` 의 `무관` 비율 > 20%** → **필터 강화**. 매칭 점수·지역 충돌 판정 쪽.
3. **사후 탈락률(최근) > 20%** → **필터 강화**. 상류가 새서 하류 AI 비용을 태우고 있다.
4. **`sample-rejected` 의 오폐기율 > 15%** → **필터 완화**. 룰 임계(길이·문체)를 재검토.
5. 위가 모두 정상인데 **`sample-summary` 불량 > 20%** → **refine 강화**. 요약 프롬프트·가드·스코어링.
6. 위가 모두 정상인데 **근거 3건 이상 lot 증가율이 목표 미달** → **수집 확대**. 필터 문제가 아니다.

한 회차에 처방은 **하나만** 적용한다. 둘을 같이 바꾸면 다음 회차 수치가 어느 쪽 때문인지 못 가른다.

## 6. 알려진 한계

- `sample-rejected` 는 2026-09-04 부터 쌓인다. 그 이전 탈락 행은 이미 삭제됐다. 첫 유의미한 오폐기 측정은 표본이 30건 모이는 시점(약 2일) 이후.
- `youtube_video` 는 크론 필터를 우회한다(수동 스크립트 대상). 백로그 항목으로만 감시하고 수율 계산에서는 뺀다.
- `filter_passed_v2` 는 배치로 소급 평가된 값이라 미평가(NULL) 행이 섞인다. 사후 탈락률은 **평가분만** 분모로 쓴다.
- 카운터는 크론 회차 끝에 한 번 기록한다. 중간에 잘린 회차는 통째로 빠진다.

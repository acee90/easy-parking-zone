# 지역 허브 색인 실험 (2026-09-14)

## 문제

GSC URL 검사에서 `/wiki/region/대전` 등 **지역 허브 17개가 전부 「크롤링됨 – 현재 색인이 생성되지 않음」** (최근 크롤 2026-09-09, Googlebot 스마트폰). 사용자 확인.

기술 원인은 아니다 (09-14 확인):

| 항목 | 상태 |
|---|---|
| HTTP / robots / canonical | 200, `index, follow`, 자기 canonical — Google 선택 표준 URL 도 일치 |
| SSR | 본문(순위 목록·구별 개수)이 원본 HTML 에 있다 |
| 사이트맵 | `sitemap-static.xml` 에 17개 모두 있다. lastmod 는 `STATIC_LASTMOD`(2026-08-03) 고정 |

Google 이 **열어 보고 거절한** 정황:

| 정황 | 측정 (09-14, Googlebot UA, 17개) |
|---|---|
| 본문이 얇다 | 헤더·푸터 뺀 텍스트 **중앙 754자** (세종 517 ~ 경기 1,622). 이름+점수+개수 목록이 대부분 |
| 허브끼리 비슷하다 | 두 허브 텍스트 유사도 **중앙 0.49, 최대 0.62** (difflib) |
| 들어오는 링크가 없다 | GSC 「참조 페이지 없음」. 유일한 색인 페이지인 홈의 원본 HTML 은 **38단어, 지역 링크 0개**. 링크는 `/wiki`(미색인)에만 17개 |
| 느리다 | TTFB **중앙 1.46s** (1.31~2.20s), 캐시 없음 |
| 허브에서 나가는 링크가 막다른 길 | 구·시·군 링크 → 307 → `&page=1` noindex 목록 |

도메인 권위(`.xyz` 신규, 백링크 0)도 배경 변수다 — 코드로 못 바꾸므로 두 그룹에 똑같이 걸린다.

## 실험 설계

**질문:** 콘텐츠 보강이 색인을 바꾸는가, 아니면 속도·링크·시간이 전부인가.

- **공통 변경 (17개 모두):** 허브·`/wiki` 로더 캐시, 지도 홈 원본 HTML 에 지역 허브 링크 17개, 구·시·군 링크를 최종 URL(`page=1`)로. (사이트맵 lastmod 고정값은 이번 범위에서 뺐다 — 거절 원인과 무관하고, 오늘 날짜로 바꾸면 lastmod 신뢰도 정책(`sitemap-handler.ts`)과 충돌한다)
- **처치 그룹 (9개) — 데이터 기반 보강:** `PARKING_REGIONS` 순서에서 짝수 번째 — **서울, 인천, 대구, 광주, 세종, 충북, 전북, 경북, 제주**
- **대조 그룹 (8개) — 보강 없음:** **경기, 부산, 대전, 울산, 강원, 충남, 전남, 경남**
- 배정은 목록 순서 교대로 미리 정했다 (결과를 보고 고르지 않는다). 두 그룹 기준선: 본문 중앙 처치 705자 / 대조 842자, TTFB 중앙 처치 1.46s / 대조 1.51s, 그룹 내 유사도 중앙 처치 0.48 / 대조 0.50 (`data/region-hub/hub-baseline-20260914.json`)
- 보강 내용은 **DB 에서 집계한 숫자와 표만** 쓴다 (AI 산문 없음 — 근접중복 위험, `project_content_enrichment_feasibility_2026_09`):
  - 유형 구성(노외·부설·노상 곳수와 비율), 무료 비율, 200면 이상 대형 곳수
  - 1시간 요금 중앙값 — 화면과 같은 `estimateFee` (계산 불가 lot 은 빼고 모수 명시)
  - 24시간 운영 곳수 — 화면과 같은 `is24HourRange` (운영시간 미상은 모수에서 빼고 명시)
  - 구·시·군별 표: 주차장 수 · 무료 비율 · 1시간 요금 중앙값
- **배포 후 사용자 작업:** GSC 에서 17개 URL 모두 「색인 생성 요청」 (같은 날, 두 그룹 똑같이)

**한계:** 9 대 8 이라 통계적 결론은 못 낸다. 방향만 본다 — 보강 그룹이 대조보다 뚜렷이 많이(3곳 이상) 색인되면 나머지 8개도 보강하고, 비슷하면 콘텐츠는 레버가 아니다.

# Issue #163 실행 계획: 상세 헤더 지도와 로드뷰 UX

## 목표

주차장 상세 헤더의 위치 지도는 유지하면서, 사용자가 진입 환경을 확인할 수 있는 네이버 로드뷰를 같은 미디어 영역에서 선택적으로 제공한다. 모바일에서 헤더 높이가 과도하게 늘어나지 않도록 지도와 로드뷰를 동시에 쌓지 않고 전환 방식으로 제공한다.

## 현재 상태

- 상세 경로: `src/routes/wiki/$slug.index.tsx`
- 지도 컴포넌트: `src/components/WikiMiniMap.tsx`
- 지도 SDK: `src/lib/naver-map-sdk.ts`
- 지도 공급자: Naver Maps JavaScript API v3
- 현재 헤더 미디어: 250px 높이의 비대화형 미니 지도
- 현재 SDK 로더는 기본 지도 모듈만 로드한다.

네이버 공식 API는 `panorama` 서브모듈과 `naver.maps.Panorama`를 통해 좌표 기반 파노라마를 제공한다. 로드뷰는 API가 지원하는 좌표와 시점에서만 표시할 수 있으므로, 모든 주차장에서 제공된다고 가정하지 않는다.

## UX 결정

### 공통 미디어 영역

- 지도와 로드뷰를 하나의 250px 미디어 영역 안에서 표시한다.
- 미디어 상단에 `지도`, `로드뷰` segmented control을 둔다.
- 기본 탭은 `지도`로 하여 기존 사용자 흐름과 초기 비용을 보존한다.
- 로드뷰 탭을 선택할 때만 panorama 서브모듈을 초기화한다.
- 탭은 버튼으로 구현하고 현재 선택 상태를 `aria-selected`로 전달한다.

### 모바일

- 기존 1열 헤더에서 미디어 영역은 동일한 높이와 폭을 사용한다.
- 지도와 로드뷰를 세로로 동시에 노출하지 않는다.
- 탭 레이블은 짧고 명확하게 유지한다.

### 데스크톱

- 기존 상세 헤더의 오른쪽 미디어 컬럼을 유지한다.
- 지도와 로드뷰를 나란히 추가하지 않아 헤더 높이와 정보 밀도를 보존한다.

## 상태 모델

| 상태 | 표시 |
|---|---|
| 지도 기본 | 지도와 주차장 마커 표시 |
| 로드뷰 초기화 중 | 미디어 영역 크기를 유지하는 skeleton/로딩 문구 |
| 로드뷰 표시 | 네이버 panorama 뷰어 표시 |
| 로드뷰 없음 | 지도 탭으로 이동할 수 있는 안내와 로드뷰 재시도 버튼 |
| SDK/파노라마 오류 | 지도 탭으로 이동할 수 있는 오류 안내 |

로드뷰의 `pano_status` 이벤트에서 실패 상태를 처리한다. 로드뷰가 없는 것은 상세 페이지 전체 오류가 아니므로, 지도 탭은 계속 이용 가능해야 한다.

## 구현 단계

1. 실행 계획 문서 작성
2. 공통 Naver Maps SDK 로더에 optional `panorama` 서브모듈 지원 추가
   - 기본 지도 페이지의 초기 로딩 계약은 유지한다.
   - 이미 기본 SDK가 로드된 뒤 상세 페이지로 이동하는 경우에도 panorama 서브모듈을 추가로 로드할 수 있게 한다.
   - 중복 script와 타임아웃을 방지한다.
3. `WikiMiniMap`을 지도/로드뷰 전환 컴포넌트로 확장
   - 지도 렌더링 로직은 유지한다.
   - panorama는 DOM ref와 `useEffect`로 생성하고 unmount 시 정리한다.
   - 외부 API 오류를 컴포넌트 내부 상태로 흡수한다.
4. 상세 헤더에 새 전환 컴포넌트를 연결한다.
5. 로드뷰 탭 선택, 초기화 실패, 데이터 없음, 재시도 동작을 테스트한다.
6. lint, test, build를 실행한다.

## 테스트 계획

- 기본 상태에서 지도 탭과 마커가 렌더링되는지 확인
- 로드뷰 탭 선택 시 panorama 서브모듈 로딩 경로가 호출되는지 확인
- `pano_status` 실패 시 오류 안내가 표시되고 지도 탭으로 돌아갈 수 있는지 확인
- 로드뷰 재시도 시 기존 미디어 영역 크기가 변하지 않는지 확인
- 지도 SDK 로딩 실패 시 기존 지도 오류 상태가 유지되는지 확인
- 모바일 폭에서 탭과 미디어 영역이 가로 넘침을 만들지 않는지 확인

## 리스크와 보류

- 좌표가 주차장 입구가 아닌 중심점일 수 있다. 이번 작업에서는 기존 lot 좌표를 기준점으로 사용하고, 입구 좌표 데이터 개선은 별도 이슈로 둔다.
- 네이버 지도 API 키의 panorama 사용 권한과 호출 제한은 배포 환경에서 확인해야 한다.
- 시각 회귀는 로컬 개발 서버에서 실제 API 키로 대표적인 모바일/데스크톱 viewport를 확인한다.

# AdSense 거절 / GSC 미색인 원인 분석 (2026-09-09)

대상: `easy-parking.xyz` (쉬운주차장)
비교군: `parking.mustarddata.com` — **경쟁사이며 우리 소유가 아니다**
(`docs/references/competitors.md:32`, `src/server/crawlers/lib/aggregator-domains.ts:22` 등재.
ads.txt pub-3224638013189545 vs 우리 pub-1181606382178400).

측정 방법: Googlebot UA 로 **raw HTML 만** fetch (JS 미실행 = Google 1차 크롤 기준).
2차 렌더링에서는 지도 API 호출 후 링크가 더 보일 수 있으나, 신생·저권위 도메인은
2차 렌더링이 배급제라 raw HTML 이 보수적 기준으로 맞다.
표본: sitemap-0~4 등간격 45건, `/wiki/all` 6개 페이지 601건.

## 요약

**지금 상황은 "크롤링이 안 되는" 상태가 아니다.** 2026-09-03 기준 Google 이 아는 URL 은
236개뿐이었고 sitemap-index 를 못 읽고 있었다. 오늘 `sitemap-index.xml` 은 정상 XML 이고
GSC 는 16,834개를 인지하고 있다. **6일 만에 약 17,000개가 발견됐다 — sitemap 수정이
먹혔고 Google 은 크롤 중이다.** 신생 도메인에 2만 URL 을 새로 제출하면 1주차에 대부분이
"발견됨 – 색인 생성되지 않음"에 쌓여 있는 게 정상이다. 2주 기다리는 판단은 맞다.

그리고 16,834 중 상당수는 **우리가 의도적으로 건 `noindex`** 일 가능성이 높다 (§1).

실제 손볼 것은 (1) 홈이 크롤 진입점으로 죽어 있다, (2) 전 페이지 `<h1>` 없음,
(3) TTFB ~1초, (4) 차별화 콘텐츠가 비어 있다 — 이 네 가지다.

## 2. 홈페이지가 크롤 진입점으로 죽어 있다

|  | easy-parking.xyz | mustarddata |
|---|---|---|
| 홈 본문 단어 수 (raw HTML) | **38** | 663 |
| 홈 내부 콘텐츠 링크 | **1개** (`/wiki`) | 17개 시도 허브 + 퀵메뉴 |
| footer | **없음** | 있음 |
| `<h1>` | **없음** | 있음 |

Googlebot 이 `/` 에서 보는 전부:

```
쉽주 — 전국 주차장 난이도 지도 … 지도를 불러오는 중...
주차장 목록 0 개  현재 지도 영역에 주차장이 없습니다
무료만 공영만 노상 제외 지금 영업중 요금 전체 50면+ 난이도
```

지도는 CSR 이라 크롤러에게 링크를 주지 않는다. 도메인에서 가장 권위 높고 가장 자주
크롤되는 페이지가 막다른 골목이다. 하위 페이지에는 footer(지역 17 링크)가 있는데
홈에만 없다.

### 발견 경로 자체는 온전하다 (수정)

초기 진단에서 "시군구 허브가 링크가 아니다"라고 봤으나 **오판이었다** — 링크 추출
정규식이 쿼리스트링을 배제했다. 실제 경로는 정상이다:

```
/wiki (index,follow)
  → /wiki/region/서울 (index,follow, 시군구 25개 <a> 링크)
    → /wiki/all?region=서울&district=강남구 (860곳, 100개씩 9홉, noindex+follow)
      → /wiki/{lot}
```

`/wiki/all?…&page=N` 은 self-canonical + `noindex, follow` + prev/next — 구현 자체는 정상.
다만 발견 골격 전체가 `noindex` 라, 장기적으로 Google 이 이 페이지들의 크롤 빈도를
낮추면 도달성이 같이 떨어진다. 지금 당장의 병목은 아니지만 감시 대상.

번호 없는 `/wiki/all` 은 54,072 ÷ 100 = **541홉** 체인이라 이 경로 하나만으로는
전량 도달이 비현실적이다. 시군구 경로(≤18홉)가 실질 경로다.

## 3. 크롤 예산: 응답이 느리다

| 페이지 | TTFB |
|---|---|
| wiki 상세 (8건) | 0.90 ~ 1.13초 |
| `/wiki` 허브 | 1.82초 |
| `/wiki/region/서울` | 1.54초 |
| `/wiki/all?page=N` | 0.91 ~ 1.08초 |

Workers + D1 SSR 이라 요청마다 쿼리가 돈다. 경쟁사는 GitHub Pages + Fastly 정적 파일이다.
Google 의 크롤 속도는 응답 시간에 반비례한다. 1초/페이지로 색인 대상 20,286개 +
발견 경로용 noindex 목록 수백 개를 돌면 크롤 예산이 빠르게 소진된다.
`발견됨 – 색인 생성되지 않음` 이 많다면 여기가 1순위다.

## 4. 페이지 자체의 결함

- ~~`<h1>` 이 한 페이지에도 없다~~ — **오진이었다.** macOS BSD grep 이 초장문 한 줄 HTML 을
  제대로 훑지 못해 0으로 나왔다. Python 으로 재측정한 실제 값:

  | 페이지 | h1 | h2 | h3 |
  |---|---|---|---|
  | `/wiki` | `전국 주차장 둘러보기` | 7 | 29 |
  | `/wiki/region/서울` | `서울 주차장` | 4 | 3 |
  | `/wiki/all` | `전체 주차장 목록` | 0 | 2 |
  | wiki 상세 **45건 전량** | 주차장명 | 9 | 2 |
  | `/` (홈) | **없음** | 0 | 0 |

  h1 이 없는 건 홈뿐이고, 홈은 헤더·푸터도 없는 전체화면 지도다
  (`__root.tsx` `showFooter = !isMap && !isAdmin`). 의도된 설계이므로
  "전 페이지 h1 부여" 작업은 불필요하다. 홈만 §2 문제로 남는다.
- **robots.txt 가 sitemap 3개를 선언**하는데 `sitemap-parking.xml`(800건),
  `sitemap-priority.xml`(220건) 은 `sitemap-index.xml` 에 없는 레거시다. 신호가 갈린다.
- `/near` 는 404. `sitemap-near.xml` 257건에 대한 허브가 없다.

정상인 것 (경쟁사보다 낫다):
- canonical 45/45, `index, follow` 45/45, description 45/45
- 사이트맵 URL 전량 정상 퍼센트 인코딩 (경쟁사는 1,812건이 raw 한글)
- JSON-LD: FAQPage, BreadcrumbList, GeoCoordinates, PostalAddress,
  OpeningHoursSpecification, WebSite+SearchAction
- 본문 SSR 단어 수 중앙값 **481** (경쟁사 328)
- 페이지 간 6-gram Jaccard 중앙값 0.18, 0.6 초과 쌍 0/990 → 중복 문서 아님
- `/about`, `/contact`, `/privacy`, `/terms` 전부 200

## 5. 차별화 콘텐츠가 비어 있다

색인 대상 45건 표본 대부분이:

```
쉬움 점수 — 첫 후기를 기다립니다
아직 리뷰가 없습니다. 첫 리뷰를 남겨보세요!
참고한 웹 글 1 건
```

헤더 집계 기준 **리뷰 240건 / 주차장 5.4만**. 사이트가 내세우는 값(난이도·실사용 후기)이
채워진 페이지가 극소수다. 나머지는 공공데이터 필드 치환 + 자동 생성 FAQ + 주변 주차장
표로, 구조는 경쟁사와 동형이다.

`크롤링됨 – 색인 생성되지 않음` 이 많다면 이 지점이 원인이다.

## 7. AdSense

### AdSense 가 보여주는 것 (2026-09-09 확인)

- 사이트 목록: `easy-parking.xyz` — 승인 상태 **주의 필요**, Ads.txt 상태 **승인됨**,
  상태 세부정보 **공란**
- 사이트 상세: "광고 게재가 준비되지 않은 사이트"
  - 사이트 소유권을 확인하세요 — **통과 (녹색)**
  - **정책 위반이 발견되었습니다** — 항목명 없음
- 정책 센터: **"정책 위반 문제 없음"** (승인 전 사이트는 정책 센터에 올라오지 않는다)

즉 **위반 항목명을 알아낼 경로가 사실상 없다.** 공식 문서도
"정책 위반사항이 있는 경우 → 프로그램 정책을 확인하세요"로 끝난다.
그러니 공식 체크리스트의 4개 원인을 하나씩 실측으로 지우는 방식으로 접근한다.

### 공식 원인 4가지 대조

[사이트에서 광고를 게재할 준비가 되지 않은 경우 취해야 할 조치](https://support.google.com/adsense/answer/12176698?hl=ko) 기준.

| 공식 원인 | 우리 상태 | 판정 |
|---|---|---|
| 광고 코드가 누락되었거나 불완전 | `src`/`public`/`dist` 전체 `adsbygoogle`·`pagead2`·`ca-pub` **0건**. 라이브 HTML `<head>` 에도 없음 (GA4 만 존재) | **해당** |
| 사이트에 접근할 수 없음 | http→https 301 ✓ · www→apex 301 ✓ · Google Trust Services 인증서 유효 ✓ · robots.txt 크롤러 차단 없음 ✓ · `Mediapartners-Google` UA 로 `/`·`/wiki` 200 ✓ · 로그인 벽 없음 ✓ | **배제** |
| 고유 콘텐츠·사용자 환경 부족 | AdSense 크롤러(`Mediapartners-Google`)가 `/` 에서 받는 본문 전체가 **38단어**: "지도를 불러오는 중… 현재 지도 영역에 주차장이 없습니다". 전 페이지 `<h1>` 0개 (§2, §4). 리뷰 240건 / 주차장 5.4만 (§5) | **해당 소지 큼** |
| 정책 위반 | 항목명 비공개 | 불명 |

### ads.txt 로는 부족하다

공식 문서상 ads.txt / 코드 스니펫 / Search Console 인증은 **"사이트를 애드센스에
연결"(= 소유권 확인)** 의 대체 수단이다. 화면에서 소유권이 녹색인 이유가 이것이다.
그런데 같은 문서의 **검토 요청 절차 4단계가 "사이트에 애드센스 코드를 삽입했는지
확인합니다"** 이고, "광고 코드가 누락되었거나 불완전한 경우" 가 준비 불가 사유 1번으로
올라와 있다. **소유권 확인과 광고 게재 준비 판정은 별개다.**

→ 코드 없이 "검토 요청"을 눌러도 같은 결과가 나올 가능성이 높다.

### 페이지 두께 자체는 거절 사유가 아니다 (반증)

mustarddata 는 페이지당 본문 **328단어**(우리 481)에, 부설주차장("모아 뉴캐슬",
"삼보빌라", "서대문경찰서 충정로지구대", 이름이 `.` 인 것까지)을
"공영 · 무료 · 24시간"으로 잘못 표기하면서도 `data-ad-slot` 이 채워진 광고를
게재 중이다 (= 승인된 계정). 우리 페이지가 그보다 얇아서 떨어진 게 아니다.

### 스크랩 콘텐츠 우려는 해소

"참고한 웹 글"이 네이버 블로그 본문을 퍼오는지 확인했다. SSR 페이로드에 저장되는 건
**제목 · 원문 URL · 호스트 · 작성자 · 게시일**뿐이고 본문 발췌는 없다.

```
title: "여의도 IFC몰 실내 가볼만한 곳! 무료 주차장팁"
sourceUrl: "https://blog.naver.com/junglks/223936781029"
author: "짤진이의 여행 플레이스"
```

인용·출처 표기 형태이고 원문으로 링크한다. "스크랩한 콘텐츠"로 바로 걸릴 구조는 아니다.
`/wiki/{slug}/media`·`/blog` 는 301, `/reviews` 는 자체 사용자 리뷰만 렌더한다.
